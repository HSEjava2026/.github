# Практическое задание: Разработка системы управления персоналом (HRM Lite) — Часть 2

## 1. Общее описание

**Цель задания:** Закрепить навыки работы с исключениями, логированием, файловой системой и отладкой в Java.

Вам необходимо расширить функционал существующего консольного приложения для управления данными сотрудников компании.

---

## 2. Архитектура приложения

Проект должен содержаться в пакете `ru.hse` и быть разделен на логические пакеты:

1. `model` — описание сущностей (POJO классы).
2. `service` — бизнес-логика приложения.
3. `presentation` — взаимодействие с пользователем через консоль.
4. `exception` — пользовательские классы исключений.
5. `repository` — работа с файловым хранилищем.
6. `util` — вспомогательные утилиты (логирование).

Main class - `HRMApplication`

---

## 3. Подробные требования к реализации

### Шаг 1: Создание пользовательских исключений

В пакете `exception` создайте следующие классы исключений:

* `EmployeeNotFoundException` — выбрасывается при попытке найти несуществующего сотрудника.
* `TaskNotFoundException` — выбрасывается при попытке найти несуществующую задачу.
* `InvalidDataException` — выбрасывается при некорректных входных данных (например, отрицательная зарплата, пустое имя).
* `DataSaveException` — выбрасывается при ошибках сохранения данных в файл.
* `DataLoadException` — выбрасывается при ошибках загрузки данных из файла.

Все исключения должны быть checked exceptions (кроме случаев, где это нецелесообразно).

---

### Шаг 2: Реализация логирования

В пакете `util` создайте класс `Logger` со следующими требованиями:

* Реализуйте логирование событий в файл `application.log`.
* Поддерживаемые уровни логирования: INFO, WARNING, ERROR.
* Каждая запись в логе должна содержать: временную метку, уровень логирования, сообщение.
* Логируйте следующие события:
  * Успешная загрузка/сохранение данных в файл
  * Создание/удаление/изменение сотрудников
  * Выброс исключений с указанием стека вызовов
  * Запуск и завершение работы приложения

Пример формата записи:
```
[2024-01-15 14:30:25] INFO: Приложение запущено
[2024-01-15 14:31:10] ERROR: Employee not found - ID: 123
```

---

### Шаг 3: Работа с файловой системой (репозиторий)

В пакете `repository` создайте класс `FileRepository` со следующими методами:

* `void saveEmployees(Employee[] employees)` — сохраняет массив сотрудников в файл `employees.dat`.
* `Employee[] loadEmployees()` — загружает массив сотрудников из файла `employees.dat`.
* `void saveTasks(Task[] tasks)` — сохраняет массив задач в файл `tasks.dat`.
* `Task[] loadTasks()` — загружает массив задач из файла `tasks.dat`.

**Требования к реализации:**
* Используйте сериализацию Java (интерфейс `Serializable`) для сохранения объектов.
* При невозможности сохранить или загрузить данные выбрасывайте `DataSaveException` или `DataLoadException` соответственно.
* Перед сохранением создавайте резервную копию существующего файла (с расширением `.bak`).
* При запуске приложения данные автоматически загружаются из файлов. Если файлов нет — создаются тестовые сотрудники (как в первой части задания).

---

### Шаг 4: Расширение бизнес-логики (`HRMService`)

Добавьте в сервис новые методы:

* `void addEmployee(Employee employee)` — добавление нового сотрудника с проверкой корректности данных (генерирует `InvalidDataException`).
* `void removeEmployeeById(Long id)` — удаление сотрудника по ID (генерирует `EmployeeNotFoundException`).
* `void updateEmployeeSalary(Long id, BigDecimal newSalary)` — обновление зарплаты (генерирует `EmployeeNotFoundException` и `InvalidDataException`).
* `void assignTaskToProgrammer(Long programmerId, Task task)` — назначение задачи программисту (генерирует `EmployeeNotFoundException`, если сотрудник не является программистом).
* `void completeTask(Long taskId)` — отметка задачи как выполненной (генерирует `TaskNotFoundException`).
* `void saveAllData()` — сохранение всех текущих данных в файлы через `FileRepository`.
* `void loadAllData()` — загрузка всех данных из файлов через `FileRepository`.

При возникновении исключений в сервисе они должны логироваться через `Logger`.

### Шаг 5: Расширение консольного интерфейса (`Reporter`)

Добавьте в меню новые пункты:

```text
=== HRM System Menu ===
1. Show all employees
2. Show filter menu
3. Add new employee
4. Remove employee by ID
5. Update employee salary
6. Assign task to programmer
7. Complete task
8. Save data to file
9. Load data from file
10. Exit
```

**Требования к вводу-выводу:**
* При вводе некорректных данных (например, букв вместо чисел) программа не должна завершаться аварийно — перехватывайте исключения, логируйте их и предлагайте пользователю ввести данные заново.
* После выполнения любой операции (кроме Exit) программа должна возвращаться в главное меню.
* При возникновении ошибок (например, сотрудник не найден) выводите понятное пользователю сообщение.

---

### Шаг 6: Отладка

В классе `HRMApplication` создайте метод `debugPrintState()`, который выводит в консоль следующую отладочную информацию:

* Количество загруженных сотрудников (отдельно менеджеров и программистов)
* Количество задач с разбивкой по статусам
* Пути к файлам хранения данных
* Время последней успешной загрузки и сохранения данных

Этот метод должен вызываться при запуске приложения в режиме отладки. Режим отладки активируется, если при запуске программы передан аргумент командной строки `--debug`.

## 4. Функциональные требования

1. При работе разрешено использовать только стандартные классы библиотеки Java.
2. Использование Collection API запрещено (работаем с массивами).
3. Все классы, которые будут сериализоваться, должны реализовывать интерфейс `Serializable`.
4. Приложение должно корректно обрабатывать ситуации, когда файлы данных повреждены или имеют неверный формат.
5. Лог-файл не должен бесконечно расти — реализуйте ротацию лога при достижении размера 5 МБ (создавайте `application.log.1`, `application.log.2` и т.д., сохраняя не более 3 архивных файлов).
6. Все ресурсы (потоки ввода-вывода) должны корректно закрываться.
7. При любом некорректном действии пользователя программа должна продолжать работу.
